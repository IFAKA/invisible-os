# Invisible controller

Android app: control the phone with one earbud button, screen off. The phone speaks the options; one click picks.

## Rules
- **No microphone. Ever.** Do not request RECORD_AUDIO, do not use SpeechRecognizer, do not add voice input or dictation. Input is only the button (click counts, hold) and, for text, the app screen or Share. Reason: the owner does not want the app to listen.
- Menu is English; message text is read in its own language (Spanish default).
- Check: `cd app && ./gradlew testDebugUnitTest --offline -q`. Install on the phone: `app/run.sh`.

## Design kits (enforced by `KitRulesTest` and the build task `checkVoiceKit`)
- Screens use only the **UI Kit** (`Ui.kt`: `Ui` colors/radii and `Kit` parts) and the **Voice Kit** (`voicekit/`, see `voicekit/KIT.md`).
- Voice Kit = everything that speaks, plays a sound, reads the button or reads a list. It has atoms, molecules, engines, organisms and one door, `VoiceKit`.
- Every spoken line is a `Phrase`. Fixed sentences live only in `voicekit/atoms/Sentences.kt`. Text from users or the world is `Phrase.content(...)`.
- Outside the kit you must not: use TextToSpeech, AudioTrack, SoundPool, MediaPlayer, ToneGenerator, audio focus, MediaSession; make `Phrase(`/`Phrase.fixed`; pass a string to `say`/`speak`; keep your own list index or loop count; write HOLD_MS/GAP_MS by hand. The build fails with file:line. The rules are in `app/voicekit-rules.tsv`.
- No `Color.*`, raw `TextView`/`Button`/`GradientDrawable` outside `Ui.kt`. If a part is missing, add it to the kit first, then use it.
- Lists: use the kit `Scanner`. Sounds: `Earcons.kt` in the kit. Check the kit with `cd app && ./gradlew checkVoiceKit --offline -q`.

## Logic Kit (check before you write any helper)
- Shared logic has a registry: `app/app/src/main/java/com/faka/invisible/logickit/KIT.md`. It lists what exists (text, language, messages, notifications, tree, tasks, learning, AI) and where. Search it and `krn find` first; reuse or extend. Never write a second copy.
- New shared pure helpers go in `logickit/` with a unit test and a row in the registry. Copying lines a second time is the sign to move them there.
- Enforced for what a pattern can catch: rule ids `logic-*` in `app/app/voicekit-rules.tsv` (now: white-space cleaning must use `squash()`/`words()`). Add a rule when you remove a duplicate.

## The OS and its programs (how every new game or tool is built)
The app is a small OS with no screen. Android is the building; this app is a shop inside it that you walk through with your ears.
- **The OS owns:** the one button (clicks and holds), the home menu (`ControllerMode`, `LauncherSettings.HUB_ITEMS`), speech, the screen tones (`voicekit/atoms/Earcons.kt`), the close sound, and the Games section (`Screen.GAMES`).
- **A program** (the Duel in `tell/`, Echo in `echo/` a rhythm-copy game, see GAME-ECHO.md, and Guard in `guard/` a beat-keeping gate game with a tutorial, see GAME-GUARD.md) owns only its own rules and sounds. It gets the raw button while it runs. It never plays an OS sound and never touches the menu.
- **To add a game:** one line in the Games list in `ControllerMode`, a `ModeOutput` start method (default no-op), one entry in `Actions` that gives it the raw button, and a callback `onEnded`. When the program ends, `Actions.gameEnded()` plays the OS close sound. Do not copy that into the program.
- **To add a tool (not a game):** one key in `LauncherSettings.HUB_ITEMS`, one case in the hub `when` in `ControllerMode`, and one tag line `Group/Sub  hub:key` in `AppCategories.kt`. The tree places it by that tag; never put a tool in the Games list. `AppCategoriesTagsTest` fails if a program has no tag.
- **Notifications (the hotel mailbox):** the listener keeps every app's notifications (`NotificationStore`); private ones (secret, locked-private, bank or password apps) are read as "<App>, new notification" only. There is no "Notifications" section: the home list is a tree of ALL apps and OS programs (`AppTree`, pure, searched for the lowest expected cost = items heard to reach an app, each level +0.5; groups from the table in `AppCategories`: Messages, Day, Money, Media, Out, Tools; the 6 groups are always direct entries of home (plus up to 2 promoted apps, home max 8), no other list over 6; there is NO "More": a place has at most 6 entries, so split crowded places with finer tags; if an untagged pile still overflows it is cut by first letters, "A to D"; flattening and promotion chosen by cost). Order comes only from use: `AppWeights` = 1 (OS programs 3) + 3 * ln(1 + month launches + 2 * week launches) + 5 * own picks (launcher and system plumbing counts 0 launches), never minutes and never notifications (the owner does not watch them; unread only appears in a label, "WhatsApp, 2"). Launch counts come from `DeviceApps` (needs usage access: `adb shell appops set com.faka.invisible GET_USAGE_STATS allow`). `AppTreeTest` prints `REPORT` lines comparing the tree with a flat list (data `src/test/resources/app_usage.tsv` from `tools/usage_weights.py`). Walk home -> group -> app. An app with notifications opens its list, then one in full with its actions plus Dismiss, Mute this app, Open app, Back; an app without opens "Open app" / "Back" (triple click goes up). The OS programs (Messages, Today, Tasks, Timer, Music, Phone, Games) are leaves of the same tree. The tree is rebuilt only when the home list is built (so picks move apps next time) and never changes while it is walked. To place a new app, add one line to the table in `AppCategories.kt`. A native module per app is one `NotificationModule` in `NotificationModules.kt` plus one line in the registry in `ControllerNotificationListener`; the chat apps (`ChatAppsModule`) are the first.
- **Find:** a hold on the home list starts Find (`Screen.FIND`, `logickit/NameFinder.kt`): pick first-letter ranges ("A to C", then "C") until the app is read; a letter with many apps reads its most used, then "Other C"; triple click = one step back. Everywhere else the hold is fast scroll.
- **Fast scroll:** hold (one long press) steps through a list fast, first word + tick; release speaks that item in full. It is only active while a list is read (`ScanList`); everywhere else a plain hold does nothing. Click then hold (2nd press held) is exit, so exit is never an accident. Every list must be a `ScanList` (enforced by `KitRulesTest`).
- **Leaving:** hold 3 s always leaves a program. Say how to leave in its first minute.
- **Teaching (research: games for blind players):** teach by short play, not by speech; one mechanic at a time (the Duel has levels 1 to 3, then the full game); confirm every success with a sound; at most 7 words per spoken sentence; pauses follow `TellVoice.pauseAfter` (600 ms + 250 ms per word); keep few sounds at once; the same sound always means the same thing; the player sets the pace; narration can always be interrupted by a press.
- **Sounds are built on a background thread** (`TellSynth.warmAsync`); the phone is about 40 times slower than the laptop for synth work. Never build sounds on the main thread.
